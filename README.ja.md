GitHub プロフィール README のための、自分の言葉で作れるすっきりした動く見出しです。URL に短い文章を書くか、「About me」や「Projects」などの組み込みの言葉を使います。リンク 1 つで切り替えられるステータスや、今日のひとことも表示できます。タイピング、ウェーブ、フェード、グローなどの効果を選んで、Markdown を 1 行貼るだけです。

上の見出しはすべて、本物の文字から作られた SVG です。[ヘルプページ](https://readmes.pages.dev/text/help)では、すべてのオプションをライブプレビューで試せます。

キーワード：動くテキスト、GitHub プロフィール README の見出し、タイピング SVG、タイピングアニメーション、波打つ文字、グラデーション文字、README の見出し、セクションタイトル、ステータスバッジ、在席ステータス、今日のひとこと、プロフィールの飾り、Cloudflare Pages Functions。

## クイックスタート

`say/` の後ろに自分の文章を書き、その行をプロフィール用の `README.md`（ユーザー名と同じ名前のリポジトリ）に貼り付けます。

```markdown
![Hi, I'm Aki](https://readmes.pages.dev/text/say/Hi%2C%20I'm%20Aki/wave)
```

日本語もそのまま使えます。

```markdown
![こんにちは](https://readmes.pages.dev/text/say/%E3%81%93%E3%82%93%E3%81%AB%E3%81%A1%E3%81%AF/wave)
```

空白は `%20`、カンマは `%2C` と書きます。これは Web アドレスに文章を入れるときの一般的な書き方です。ヘルプページのビルダーがこの変換を自動でしてくれます。お好みで、`/text/wave?text=Hi%20there` のようにクエリとして同じ文章を渡すこともできます。

自由な文章は 60 文字まで、どの言語でも使えます。`https://` や `www.` のようなリンクは受け付けないので、見出しを広告にされることはありません。

よく使うセクション名なら、組み込みの言葉を使えば変換の手間が省けます。

```markdown
![About me](https://readmes.pages.dev/text/about-me/wave)
```

README 全体のセクションタイトルとして使えます。

```markdown
![Projects](https://readmes.pages.dev/text/projects/underline)
...
![Contact](https://readmes.pages.dev/text/contact/underline)
```

中央揃えにしたい場合は HTML を使います。

```html
<p align="center">
  <img src="https://readmes.pages.dev/text/hello/typing/size-56" alt="Hello!">
</p>
```

## なぜ見出しを画像にするのか

Markdown の見出しは素朴で、どのプロフィールでも同じに見えます。README の冒頭やセクションの間に、もう少し個性がほしい人は多いはずです。GitHub は README から独自の CSS やスクリプトを取り除くので、スタイルや色や動きを加えるには画像を使うしかありません。

ところが、見出し画像の多くはスクリーンショットや GIF です。重く、高精細な画面ではぼやけ、色も固定なのでダークモードでは浮いてしまいます。この見出しは違います。本物の文字と数行の CSS が入った SVG ファイルです。どの大きさでも小さくてくっきりしていて、見る人のライト／ダークのテーマに合わせ、スクリプトなしで動きます。

## 効果

効果は 1 つのオプションで選びます。同時に使える効果は 1 つだけですが、色や飾りはどの効果とも自由に組み合わせられます。

`typing` は、点滅するカーソルの後ろに 1 文字ずつ文字を打ち込みます。全体をしばらく表示したあと消して、また最初から始めます。定番のターミナル風の見た目で、短いあいさつにいちばん合います。

`wave` は、文字が順番に上下に揺れ、さざ波が通り抜けるように見えます。にぎやかですが読みやすく、遊び心のあるプロフィールに向いています。

`fade` は、文字を左から右へ浮かび上がらせます。少し間を置いてから、同じ順番で消えていきます。落ち着いた上品な印象で、セリフ体とよく合います。

`glow` は、文字を動かさずに、背後にゆっくり脈打つやわらかな光を加えます。ダークモードでアクセントカラーと組み合わせると特にきれいです。

`none` は既定値で、動きなしで文字を描きます。邪魔をしてはいけないセクションタイトルに最適です。

`speed-N` は、どの効果の速さも 25 から 400 パーセントの範囲で変えられます。`static` は、虹色やきらめきも含めて、すべての動きを止めます。

## ステータス

`/text/status` は、「Open to work」「Busy」「On vacation」のような今のステータスを表示します。README を編集する代わりに、秘密のリンクで選びます。この画像を表示しているすべてのプロフィールとページが、1 分ほどで更新されます。

`readmes.pages.dev` のデモでは、スタイルを試せるようにサンプルのステータスを表示しています。自分のステータスを表示するには、下の説明に従ってコピーをデプロイしてください。ステータスの一覧は、1 行に 1 つずつ、非公開の環境変数に入れます。

```
Writing code
In a meeting
Open to work
On vacation until Monday
```

切り替えは、トークンを付けたリクエスト 1 回だけです。

```sh
curl https://my-badges.pages.dev/text/swap/<token>        # 次のステータス
curl https://my-badges.pages.dev/text/swap/<token>/4      # 4 番目のステータス
curl https://my-badges.pages.dev/text/state/<token>       # 一覧と現在のものを確認
```

間違ったトークンには、存在しないページと同じ 404 が返るので、切り替えが有効かどうかを外から知ることはできません。ステータスの画像はキャッシュされないので、変更はほぼすぐに訪問者に届きます。

### よいステータスの書き方

ステータスは、見た人が行動を起こせるものがいちばんです。「Open to work」は連絡を促し、「On vacation until Monday」はいつ返事が来るかを伝えます。長いものより短いもののほうが読みやすく、たいていは数語で十分です。

一覧は小さく、予測しやすく保ちましょう。5 個から 10 個あればたいていの状況をカバーでき、番号も覚えられるので `/text/swap/<token>/<n>` ですばやく切り替えられます。最初の状態は 1 番目の項目なので、いちばんよく使うステータスを先頭に置きましょう。

正確な旅行の日程やイベントの住所など、知らない人に読まれたくないことは書かないでください。プロフィールは公開されていて、画像に表示されるものもすべて公開されます。

## ひとこと

`/text/quote` は、一覧から 1 行を表示します。ページを開くたびに新しいものを選ぶか、`daily` を付けると 1 日 1 つになります。デモでは、短いオリジナルの言葉をいくつか使っています。自分のコピーでは、非公開の環境変数から 1 行に 1 つずつ一覧を読み込みます。

プロフィールに向くひとことは短いものです。60 文字までなら README にきれいに収まり、80 文字を超えた部分は切り捨てられます。誰かの言葉を引用するときは作者を明記し、最近の本からの長い引用は著作権で保護されている場合があることを覚えておいてください。

### ランダムか、日替わりか

ランダムなひとことはページを開くたびに変わるので、何度も訪れる人へのちょっとしたごほうびになります。日替わりのひとことは UTC の 0 時に 1 日 1 回変わるので、同じ日に訪れた人は全員同じ 1 行を目にします。ほかの内容の隣に置いて、偶然ではなく意図して選んだように見せたいなら、日替わりのほうが向いています。

30 個ほどのひとことと `daily` を組み合わせれば、1 か月は同じものが出ません。新しい行はいつでも追加でき、次に一覧が読み込まれたときに表示されます。

セリフ体で 22〜28 ピクセルくらいの控えめな大きさにすると、本の一節のように読め、見出しの下にしっくり収まります。`fade` 効果を使えば言葉がいっぺんにではなく、やさしく現れるのでよく合います。もっと落ち着いたページにしたいなら、日替わりのひとことに `static` を組み合わせると、動かずに毎日変わります。

## 見出しを使ったプロフィールのデザイン

名前の近くに、印象的な見出しを 1 つ置くところから始めましょう。タイピング効果の `hello` や、ウェーブの `welcome` などです。それで雰囲気が決まります。その下は、`about-me`、`projects`、`contact` のような動きのない見出しを各セクションに使います。動く文字だらけのページは、すぐに読み疲れてしまいます。

大きさを揃えましょう。56 ピクセルくらいの大きなあいさつと、28〜32 ピクセルくらいのセクションタイトルを組み合わせると、表題と章のある文書のように、はっきりした階層ができます。

フォントはプロフィールの他の部分に合わせましょう。sans は中立的でモダン、serif は書き手や研究者に、mono はターミナルやハッカーの雰囲気に合います。フォントを混ぜてもあまりよいことはないので、1 つ選んですべての見出しに使ってください。

### 色の選び方

特に理由がなければ、テーマは `auto` のままにしておきましょう。そうすれば、GitHub の他の部分とまったく同じように、暗い背景では明るい文字に、明るい背景では暗い文字になります。

色を使いたいなら、`color-RRGGBB` でアクセントカラーを 1 つ選び、すべての見出しと下線に使いましょう。`gradient` と `rainbow` は目を引くあいさつ 1 つには楽しいですが、すべてのセクションタイトルにはあまり向きません。

決める前に、ライトモードとダークモードの両方で確認してください。GitHub ではアカウント設定でテーマを切り替えられるので、それがいちばん手早い確認方法です。

## オプション

オプションは `/text/` の後ろに続くパスの部分で、順番は自由です。末尾に `.svg` を付けてもよく、大文字と小文字は区別しません。書き間違えると、画像の代わりに不明なオプションの位置を示すピンク色の小さな通知が出ます。

| オプション | 効果 |
|---|---|
| `say/<text>` | 自分の文章。60 文字まで、URL エンコードして書く |
| `?text=...` | 同じものをクエリパラメーターで |
| 表の言葉 | その見出し（既定は `hello`） |
| `status`、`quote` | 言葉の代わりにステータスやひとことを表示 |
| `daily` | `quote` と一緒に使うと 1 日 1 行 |
| `typing`、`wave`、`fade`、`glow`、`none` | 効果（既定は `none`） |
| `speed-N` | 効果の速さ（パーセント）、25 から 400 |
| `static` | 動きを一切なくす |
| `sans`、`serif`、`mono` | フォント（既定は `sans`） |
| `size-N`、`size-Nrem` | 文字サイズ（ピクセル）、16 から 96（既定 40） |
| `px` | rem ではなく正確なピクセルに固定（下記参照） |
| `color-RRGGBB` | 文字とアクセントの色（16 進数、`#` なし） |
| `gradient` | オレンジからピンク、ラベンダーへのグラデーション |
| `rainbow` | 1 文字ずつ違う色が、ゆっくり移り変わる |
| `upper`、`lower` | 大文字・小文字の変換 |
| `underline` | 文字の下に角の丸いアクセントの線 |
| `sparkles` | 文字の周りにきらめき |
| `card` | 角丸のカードの背景 |
| `border-N` | カードの枠線（ピクセル）、0 から 8 |
| `auto`、`light`、`dark`、`transparent` | テーマ（既定は `auto`） |

### rem でのサイズ指定

どの見出しも rem でサイズが決まっていて、1rem は 16 ピクセルです。ブラウザーの既定の設定では、ピクセル指定とまったく同じに見えます。文字を読みやすくするためにブラウザーの既定の文字サイズを大きくしている人には、周りの文字と同じように見出しも大きくなります。`size-2rem` のように rem でサイズを書くこともでき、これは GitHub の Markdown の `#` 見出しと同じ大きさです。正確なピクセルのサイズを保ちたい場合は `px` を付けてください。

## しくみ

見出しは 1 文字ずつ描かれます。サーバーは 3 つのフォントファミリーのすべての文字幅を知っています。これは、Arial、Times New Roman、Courier New と同じ寸法のフォントから一度だけ測ったものです。その幅をもとに、各文字を正確な位置に置きます。文字が 1 つずつ分かれているので、CSS で 1 文字ずつ別々のタイミングで動かしたり、消したり、色を付けたりできます。だからこそ、スクリプトなしでタイピングやウェーブやフェードが実現できます。

フォントそのものは、訪問者の端末のものが使われます。Windows には Arial と Times New Roman、macOS には寸法が互換の Helvetica と Times、Linux にはたいてい Liberation フォントがあります。どれも文字幅が同じなので、どこでも間隔が揃います。

日本語のように英語以外の文字は、訪問者のシステムフォントで表示されます。そうした文字の間隔は推定値ですが、全角の文字ではうまく機能します。

### サイズと速さ

見出しはたいてい 1〜4 KB で、同じ文字の動く GIF よりはるかに小さくなります。タイピング効果は 1 文字ごとの段階を記述するのでいちばん大きくなりますが、それでもほとんどのアイコンより軽量です。見出しの多いページでも、遅い回線ですばやく読み込めます。

組み込みの言葉は 1 日キャッシュされるので、2 回目以降の表示は一瞬です。ステータスとランダムなひとことは常に最新である必要があるためキャッシュされませんが、数ミリ秒で生成されます。

### 他のウィジェットとの組み合わせ

見出しは、同じサイトの他のウィジェットと自然に組み合わせられます。「Now」の見出しの下に時計を置けば、あなたのところが今何時かが伝わります。「Contact」の下にメールバッジを置けば、アドレスを文字としてさらさずに連絡手段を示せます。見出しの横に小さな動く顔文字を置けば、ちょっとした個性が加わります。

どれも同じアクセントカラーとテーマに揃えれば、ページはばらばらの画像の寄せ集めではなく、1 つのデザインとして見えます。

## アクセシビリティ

各画像は文字をタイトルとして持っています。`![About me](...)` のように、代替テキストにも同じ言葉を書いてください。そうすればスクリーンリーダーは見出しを普通に読み上げます。

システムで動きを減らす設定をオンにしている訪問者には、アニメーションなしの完成した文字が表示されます。Windows では、アクセシビリティ設定の「アニメーション効果」をオフにするとこうなります。既定の色は、GitHub の明るい背景と暗い背景のどちらでも WCAG AA のコントラストを満たしています。白の上で映える色が黒の上では見えなくなることもあるので、自分で選んだ色は両方のテーマで確認してください。

動く文字が気になって集中できない読者もいます。プロフィールの冒頭に動く見出しを 1 つ、その下のセクションには動きのない見出しか `static` を使う、というのがよい目安です。

## 自分のコピーを動かす

自分のステータスやひとこと、追加の言葉を使いたいときは、コピーを用意しましょう。Cloudflare Pages なら無料で、10 分ほどで済みます。

必要なのは Node.js 20 以降、`make`、そして無料の Cloudflare アカウントです。依存パッケージがないので `npm install` はありません。

1. GitHub で「Use this template」を押してリポジトリを作り、クローンします。
2. `site.config.json` に自分の名前とリポジトリのリンクを入れます。
3. Pages プロジェクトと、ステータス用の小さなキーバリューストアを作ります。

```sh
npx wrangler pages project create my-badges --production-branch production
npx wrangler kv namespace create text-state
```

4. `wrangler.toml.example` を `wrangler.toml` にコピーし、プロジェクト名と名前空間の ID を入れます。本物の `wrangler.toml` は Git には入りません。
5. ステータスとひとこと（1 行に 1 項目の `STATUSES.txt` と `QUOTES.txt`）、そして長いランダムなトークンをシークレットとして保存します。

```sh
for v in STATUSES QUOTES; do
  npx wrangler pages secret put "$v" --project-name my-badges < ~/private/"$v".txt
done
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
npx wrangler pages secret put TEXT_SWAP_TOKEN --project-name my-badges
```

6. `make deploy PROJECT=my-badges` でデプロイします。

言葉を追加するには、`src/text/content.js` の一覧を編集します。各項目は、URL の名前と描かれる文字の対応です。

### プロジェクトの構成

```
functions/text/         Pages Functions：見出し、切り替え、状態、ヘルプ、エージェント
src/text/content.js     組み込みの言葉、デモのステータスとひとこと
src/text/render.js      文字の配置、効果、飾り
src/text/handler.js     ステータス、ひとこと、トークン付きリンク
src/text/pages.js       URL ビルダーとエージェント向けガイド
scripts/build-metrics.mjs  文字幅の再計測（ImageMagick）
test/                   node:test の単体テスト
```

すべて `text` のパスの下にあるので、このプロジェクトはファイル名をぶつけることなく、他のバッジアプリと 1 つの Pages プロジェクトを共有できます。

## Web ページ

| パス | 内容 |
|---|---|
| `/text/help` | 例、ライブプレビュー付きの URL ビルダー、オプション一覧 |
| `/text/agents` | AI エージェントやツール向けの Markdown ガイド |

これらのページには Open Graph タグと schema.org の JSON-LD、キーボードのフォーカス表示、スキップリンクがあります。プレビューのデプロイには自動で noindex が付き、スクリプトは厳格なコンテンツセキュリティポリシーによりハッシュで許可されたものだけが動きます。

## よくある質問

### URL に好きな文章を書けますか？

はい。`say/` の後ろに文章を続けます。どの言語でも 60 文字まで使えます。リンクは受け付けず、制御文字は取り除かれます。自分のコピーが必要になるのは、リンクで切り替えるステータスや、自分のひとことの一覧を使いたいときです。

### タイピング効果が最初からやり直すのはなぜ？

プロフィールの見出しは、人によって違うタイミングで目に入ります。繰り返すことで、いつ訪れても数秒以内に全体を読めるようにしています。

### ステータスが変わらない

1 分待ってから再読み込みしてください。変更は 60 秒ほどですべてのエッジに届き、画像はキャッシュされません。それでも古いままなら、トークンを確認し、`/text/state/<token>` でどの項目が有効か見てください。

### ステータスの変更を予約できますか？

組み込みの機能はありません。切り替えは Web リクエスト 1 回なので、cron やカレンダーの自動化など、普段使っているスケジューラーから送れます。トークンは、人と共有するスクリプトではなく、そのツールのシークレット保管場所に入れてください。

### 見出しは他の言語でも使えますか？

はい。自由な文章には日本語や中国語などの文字も使えます。そうした文字は訪問者のシステムフォントで、推定した間隔で描かれます。全角の文字では自然に見え、一部の文字ではやや間隔が広く見えます。

### GitHub 以外でも使えますか？

はい。個人サイト、ドキュメント、他のコードホスティングなど、画像の URL を表示できる場所ならどこでも使えます。

## トラブルシューティング

### 画像が「unknown option」になる

通知は、認識できなかった部分の位置を、`/text/` の後ろの最初の部分から数えて示します。言葉の一覧とオプションでつづりを確認してください。2 語からなる言葉は `about-me` のようにハイフンでつなぎます。

### 文字が重なる、または間隔がばらつく

端末に Arial、Helvetica、Liberation Sans のどれもない場合に起きますが、めったにありません。その場合、ブラウザーは幅の違うフォントで代用します。`mono` に切り替えると直ります。等幅フォントはすべての文字が同じ幅だからです。

### アニメーションが再生されない

システム設定で動きを減らす設定がオンになっていないか確認してください。Windows ではアクセシビリティ設定の「アニメーション効果」のスイッチです。エディターの Markdown プレビューの中には静止画しか表示しないものもありますが、GitHub 自体はアニメーションを再生します。

### ステータスのリンクが 503 を返す

トークンは正しいのですが、デプロイにキーバリューストアがありません。`wrangler.toml` に `TEXT_STATE` のバインディングを追加して、もう一度デプロイしてください。

## プライバシー

デモは何も保存しません。アップロード、フォーム、Cookie、アクセス解析はありません。各画像は URL のパスだけから計算されます。

自分のコピーで保存されるのは、現在のステータスの番号だけです。ステータス、ひとこと、トークンは暗号化された Cloudflare のシークレットに入り、リポジトリには一切現れません。表示しているステータスやひとことは、プロフィールを訪れるすべての人に公開されることを忘れないでください。

GitHub では画像は GitHub のプロキシ経由で取得されるので、サービスはふつうプロフィールを見ている人の IP アドレスを知ることはありません。どの Web サイトとも同じく、Cloudflare は独自の[プライバシーポリシー](https://www.cloudflare.com/privacypolicy/)に従って標準的なリクエストのログを保持することがあります。
